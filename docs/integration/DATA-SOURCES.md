# Where the data comes from

## Shipped assets (default)
`assets/operations/disruptionops-taxonomy.json` is generated by `tools/build_taxonomy.py` from DisruptionOps migrations 001-036 (commit `1697407df41d77ff741aec6b4ad4e489a04a4f9e`), replaying inserts, `on conflict do update` upserts and the 007 `serves_public` update. Counts: 5 hazards, 12 capabilities, 11 resource kinds, 16 incident categories (147 keywords), 11 lifeline kinds, 20 agencies. `agency-catalog.json` (PCMC units, lifelines, wards) comes from migration 029, unchanged since `bd21179`. Refresh: `python tools/build_taxonomy.py --source <DisruptionOps checkout> [--catalog]`; `--check` exits 1 if stale.

## Live mode
Set `DISRUPTIONOPS_URL` (and `DISRUPTIONOPS_TOKEN`). `swarm_ops.disruptionops_client.load_reference_data()` returns `{mode, taxonomy, catalog, incidents, ...}` in the same shapes as the assets and falls back to them (logged, `mode: assets-fallback`) if the upstream is unreachable. Cached 300 s. Tested only against a local stub server, never a real deployment.

| Call | Auth | Upstream source (backend/app) |
|---|---|---|
| `GET /api/v1/taxonomy?city_id=pune` | public | `api/v1/runs.py:47` |
| `GET /api/v1/wards` | public | `api/v1/geography.py:13` |
| `GET /api/v1/lifelines` | public | `api/v1/geography.py:18` |
| `GET /api/v1/incidents` | any caller | `api/v1/operations.py:30` |
| `GET /api/v1/resources` | staff bearer JWT | `api/v1/operations.py:35` |

Router prefix `/api/v1`: `main.py:156`. Bearer verification: `core/security.py:111-132`. Responses are camelCase (`schemas/domain.py` `Camel`). Known gaps: the taxonomy API omits per-kind `effectiveness` (`domain.py:422`), so it is merged from the asset (default 1.0); keywords arrive as `{phrase: weight}`; resources lack `agency_id`, taken from the asset catalog or matched by operator name. Only ids starting `w-pc-`, `lf-pc-`, `PC-` are used.

## Aerial capability decision
No `drone` resource kind: `agents/replan.py:933` (`_air_matrix`) skips kind `drone`, so the solver would route it on roads. The swarm is the `drone-swarm` agency (migration 040) reached through `/agency-requests` (`api/v1/reports.py:281`).

## Upstream f7ca6d8 (migrations 001-038)
`disruptionops-taxonomy.json` is regenerated at f7ca6d8; 037 (held unclassified reports) and 038 (agency replies) add no taxonomy rows. Behavioural changes that matter: `GET /incidents` no longer lists `unknown_report` incidents; `agency_requests` carry `reply_kind`/`replies`/`units` (`ops/agency_replies.py`).
